# IP-Relay Testing Solution - Plan

## Goal
Validate the core concept: remote client traffic routes through a static IP exit point via WireGuard reverse tunnel.

## Scope (MVP Testing)
- No authentication, no dashboard, no database
- Minimal, hardcoded setup to prove the tunnel works
- Single GCP VM relay, single exit agent

## Architecture

### 1. GCP Relay VM Setup
- Ubuntu 22.04 LTS on GCP Compute Engine
- WireGuard installed and configured as hub
- IP forwarding and NAT/masquerading enabled
- Simple HTTP API (FastAPI or Node) to:
  - Generate WireGuard key pairs
  - Add/remove peers via CLI or simple endpoint
  - Report tunnel status

### 2. Exit Agent (Home/Office PC)
- Bash script (cross-platform wrapper for Windows/Mac/Linux)
- Installs WireGuard
- Connects to GCP relay via reverse tunnel with `PersistentKeepalive = 25`
- Verifies public IP matches expected static IP
- Logs connection status

### 3. Remote Client Setup
- Manual WireGuard config file (generated by relay API)
- Connect to relay VM
- Route all traffic through tunnel
- Verify public IP shows as exit agent's static IP

## Implementation Steps

### Phase 1: GCP Relay VM
1. Provision Ubuntu 22.04 VM on GCP
2. Install WireGuard
3. Enable IP forwarding: `net.ipv4.ip_forward=1`
4. Configure iptables for NAT/masquerading
5. Create simple Python/Node API endpoint to:
   - Generate key pairs
   - Output WireGuard peer config
   - Accept peer additions (hardcoded for testing)

### Phase 2: Exit Agent Script
1. Create bash script that:
   - Detects OS (Linux/Windows/Mac)
   - Installs WireGuard
   - Accepts relay VM IP and keys as parameters
   - Configures WireGuard with reverse tunnel
   - Sets `PersistentKeepalive = 25`
   - Verifies public IP via curl to icanhazip.com
   - Logs status

### Phase 3: Remote Client Config
1. Generate WireGuard config from relay API
2. Manually add to remote device
3. Connect and test
4. Verify public IP matches exit agent's static IP

## Testing Flow
1. Start GCP relay VM with WireGuard
2. Run exit agent script on home/office PC
3. Generate client config from relay API
4. Connect remote device to tunnel
5. Check public IP on remote device
6. Confirm it matches exit agent's static IP

## Deliverables
- GCP VM setup script (terraform or manual steps)
- Relay API (simple endpoint to generate configs)
- Exit agent bash script
- Client config file (generated)
- Test results documentation

## Success Criteria
- Exit agent connects to relay VM
- Remote client receives config and connects
- Public IP on remote client = exit agent's static IP
- Tunnel remains stable for 5+ minutes

## Not Included (Phase 2+)
- Authentication
- Dashboard
- Database
- Multi-region support
- Key rotation
- Audit logging
